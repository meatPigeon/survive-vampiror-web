# Horde encounter

The initial one-knight slice was expanded into a native port of the sibling Godot game at source commit `dc97542e57888c82ab18c6b8a47c9294192bf3bb` (Submission Update). The user asked for the full reference game, including testing, GitHub pushes and staged DEV uploads. Keep the source game's rules and authored assets as the baseline when extending this module.

The current local iteration extends that three-wave baseline into a five-location march. Its intentional rule changes, new attacks and passive perks are recorded in [Conquest campaign](conquest-campaign.md). The three-wave tables and staged receipts below describe the original port and earlier uploads.

The game runs in Three.js inside the existing iDos module host. It is not a Godot export or iframe. `horde` replaces `mini-game` in the composition; the unregistered starter remains as a catalog reference. The base handles sign-in, lobby and shared UI. Encounter state is local and does not grant platform currency, report arbitrary scores or complete platform quests. Those integrations require a separately scoped request and configured IDs.

## Rules and lifecycle decisions

The pure simulation is deterministic for a supplied seed and uses a 60 Hz fixed step. Its frame order follows the source: horde movement, lifetime expiration, abilities, site schedule, knight, zombie bites, then recruitment. This preserves outcomes such as permanent-wipe defeat taking priority over mine damage, and expiring sling ammo disappearing before impact. Pause, reward selection and wave breaks freeze gameplay clocks. Focus loss clears held input and sling aim without automatically pausing, matching the source.

Keyboard, touch and bounded agent movement feed the same input object. A brief first movement starts the battle immediately, including when key-up occurs before the next physics frame. Host suspension removes listeners, stops RAF and pauses audio; returning resumes the saved encounter. Restart resets all encounter systems and camera framing. The SDK scene's ready promise waits for assets; capture renders immediately before reading the canvas. JSON-safe `ctx.exposeToAgent` state and bounded movement, sprint, ability, aim/fire/cancel and zoom actions use the normal gameplay gates. DOM menu/reward controls are not duplicated in agent actions.

Random rewards, site choice and sling scatter use independent seeded web RNG, rather than Godot's global RNG. Probabilities and selection constraints match; identical engine RNG sequences are not promised. Three.js lighting and browser text/layout are engine adaptations, so pixel-identical rasterization is not claimed. Touch controls are a web addition. Source art, geometry, attack clips, constants and gameplay behavior remain the reference.

## Recruitment and planted mines

The user requested two more temporary-recruit craters and mines that use only temporary zombies and let the horde walk past. This intentionally changes the Godot baseline: keep these web rules when refreshing source assets or porting further behavior.

West, South and East keep their original indexes; North `(6, -13)` and Northeast `(22, -7)` extend the site list to five. Only one site is active at a time, starting West and choosing a different site each rotation. Recruitment timing, stock, lifetime and capacity are unchanged. Rendering and the procedural ground shader derive their site counts/activation arrays from `SITES`, so both added craters have the same graves, progress and glow behavior.

Corpse mines choose half of the alive, unlocked temporary recruits, rounded down with a minimum of one. Permanent zombies, dead recruits and already locked sling ammo are never selected. Without an eligible recruit the ability is disabled and spends no cooldown. Armed recruits stay locked in place, cannot bite or become sling ammunition, and keep the two-second fuse and existing blast damage. The moving horde skips armed bomb IDs during separation, allowing it to walk through their positions; this does not change collision against other locked zombies. Existing lifetime expiry and knight damage can still remove a bomb before it explodes. Pause, wave breaks and terminal outcomes retain their normal priority. Their low idle pose, pulsing orange ring and amber fuse distinguish planted mines from walking recruits; the fuse is actor-owned, hidden on cancellation/death and disposed at teardown.

## Assets and reproducibility

The committed reference assets are user-owned scenes/art/audio/fonts from the sibling project. `npm run assets:port` runs `scripts/port-assets.gd` with Godot 4.7.2, exports runtime-authored bite/knight animation libraries along with the authored geometry, then copies audio/fonts/UI art and writes a revision/hash manifest. The original font licenses are included. See [asset notes](../../src/modules/horde/assets/reference/README.md). Vite emits relative fingerprinted URLs for version-path hosting. Runtime builds do not depend on Godot.

`SkeletonUtils.clone` gives each actor an independent skeleton/mixer. Shared source geometry/materials belong to the asset cache; instance hit materials, markers and stream geometry are disposed with each actor. The menu, actor, equipment and environment scenes retain source transforms rather than replacing them with placeholders.

## Web visual treatment

The user requested a visual appeal pass and shader experiments after the gameplay port. This deliberately moves the web lighting beyond source rasterization while preserving the three-wave simulation, camera controls, model scale and authored animations. Ten-wave expansion was discussed only as brainstorming and is not implemented.

`material-look.ts` supplies cool hemisphere/moon lighting, a warm fill, ACES tone mapping, soft mint/gold character rim light and a continuous procedural moss/dirt surface. The exported `GroundPatches` group is hidden at runtime because its flat overlapping polygons obscured that surface; the original GLB remains unchanged. Warm ground light pools and the active recruitment glow use shader terms, avoiding eight extra point lights. Shader extensions use Three.js's [material compile hooks and program cache keys](https://threejs.org/docs/pages/Material.html). Actor-owned cloned hit materials reapply the rim hook, since material cloning does not carry shader callbacks. Skinning, source colors and shadow sampling remain in the standard material pipeline.

`graveyard.ts` adds candles, source tombstones and instanced worn boundary stones outside the movement rectangle. These props do not create collision. Flames flicker only while the view advances; pause/host suspension therefore freeze them. The renderer now selects supported `PCFShadowMap` directly.

`effects.ts` draws 64 ambient motes and a fixed 320-slot additive spark pool for bites, recruitment, mines and sling impacts. Large bursts overwrite older slots rather than growing resources. Restart clears particles; teardown disposes both point geometries/materials and instanced GPU buffers. No textures, downloaded art, new dependencies or fullscreen bloom passes are required. Attack borders follow the existing exact sector/circle/lane dimensions, and windup fill intensifies without changing hit timing or area. Impact rings expand and fade independently of damage.
